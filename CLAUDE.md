# giacomo-ravetta-site

Personal site of Giacomo Ravetta. Astro 7 + Tailwind 4 + GSAP + Three.js (background only), fully static, deployed to Cloudflare via `@astrojs/cloudflare`. Bilingual (English at `/`, Italian at `/it/`) through Astro's built-in i18n and the dictionary in `src/i18n/ui.ts`.

## Working rules

- **Do not use MCP servers unless the task actually requires them.** Prefer local tools (file reads, grep, the shell, `npm run build`). Only reach for an MCP server (Playwright, Sanity, docs, etc.) when the task cannot be completed or verified without it, e.g. a visual check the user explicitly asks for.
- Don't commit or push unless asked.
- Keep the site static and dependency-light. Ask before adding packages.

## Commands

- `npm run dev` — dev server on http://localhost:4321 (Astro daemonises it; `npx astro dev stop` to stop).
- `npm run build` — `astro check` + production build. Run this to validate changes. The build uses its own Vite cache dir (`node_modules/.vite-build`) so it no longer breaks a running dev server.

## Structure

- `src/pages/*.astro` English pages; `src/pages/it/*.astro` thin wrappers with Italian slugs. Add a route key in `src/i18n/ui.ts` (`routes`) for each new page; slugs may be nested (`services/automation` ↔ `servizi/automazione`).
- Fonts (self-hosted in `public/fonts`, all OFL): Instrument Sans variable (`font-instrument`) for text; Bluu Next Bold (`font-bluu`) for headlines and the Web service; Young Serif Bold (`font-young`, Open Foundry, Latin subset) for "About me" (split into letters by `SplitWord.astro` for the letters-rise CSS animation) and the AI service; Terminal Grotesque (`font-terminal`) for Automation; condensed bold Instrument Sans for Data visualization.
- `src/layouts/BaseLayout.astro` — head, site background, header, footer. `fullBleed` prop drops the content container; `bgColour` / `bgShape` tint and shape the 3D background.
- Services: four of them — Web design & development (`web`), AI integration (`ai`), Automation (`automation`), Data visualization (`dataviz`). All content, key colours and title faces live in `src/i18n/services.ts` (`services`, `serviceStyle`, `serviceIds`; each id is also a route key). `src/pages/services.astro` shows one panel per service: four side by side and exactly one viewport tall on xl+ (`calc(100dvh - var(--header-h))`, sizes scale with dvh), two per row on tablets, stacked on phones; hovering a panel (mouse only, xl+) pops in the marks of its tools from `src/lib/tool-icons.ts` (Lucide line icons, Simple Icons logos, and hand-drawn concept icons) at random free spots that avoid the text and each other, then they float gently. Each panel links to its subpage, rendered by `src/components/ServiceList.astro` (title, summary, "what it includes" items, "what it brings" benefits, contact CTA).
- Work: `src/pages/work.astro` lists the projects from `src/i18n/work.ts` (each with thematic tags; tag labels EN/IT there, titles/descriptions in ui.ts `work.<key>.*`). A tag filter bar (hidden without JS) shows only projects with the chosen tag, keeps it in `?tag=<id>` (shareable), and tags on the cards select/clear that theme.
- `src/components/Header.astro` — desktop: floating frosted-glass sticky bar (76dvw up to 72rem, py-6, text-lg name and text-base links, `glass` utility in global.css, shared with the footer, a content-width tab with square bottom corners), flow height `--header-h` in `src/styles/global.css` (keep in sync). Phones: compact full-width bar fixed over the content plus a full-screen menu (`[data-menu]`, toggled by `[data-menu-toggle]`); container pages add `max-md:pt-32` to clear it.
- `src/components/SiteBackground.astro` + `src/lib/site-background.ts` — the site-wide 3D background (Three.js, the only place it is used; imported dynamically when the browser is idle, ~135 kB gzipped). A fixed canvas behind every page shows one mesh as its topology: a quad-sphere (cube faces pushed onto a sphere, so all quads) whose surface flows through a shared vertex-shader displacement, drawn as edge loops (`LineSegments`), glowing vertices (`Points`) and a dark body that hides the far side and catches a rim of the key colour; a scan band sweeps across it. It turns slowly, leans towards the mouse and with the scroll. The sphere mutates into a shape per service (`SHAPES` in site-background.ts: browser window for Web, sparkle for AI, gear for Automation, bar chart for Data visualization): same vertices, morph targets as vertex attributes; a change goes from `uFrom` to `uTo` (one-hot `Vector4`s, all zeros = the sphere; note `new Vector4()` has w = 1) driven by `uProgress`, sweeping through the mesh along a random `uAxis` as a wave: each vertex leaves a little later, swings around the axis, overshoots, settles, and is lit while in flight. With nothing hovered (and so always on touch screens) the mesh tours the shapes of the services present on the page (Home, Services), then the sphere, and sets `data-svc-active` on the matching link/panel so it lights up; no tour with reduced motion. The shape and colour follow any hovered/focused element with `data-svc-id` + `data-svc-key` (Home service links, Services panels; the script in SiteBackground.astro copies them to `data-bg-shape`/`data-bg-key` on `<html>`), and a service subpage keeps its own shape (`bgShape`). While a shape is up the mesh stops spinning and faces the viewer. `?shape=<id>` forces a shape for previews. Headless Chrome renders only a frame or two of it: to screenshot a shape use `--force-prefers-reduced-motion` (still frame, no fade), and add `&progress=0.5` to freeze a change part-way. Home (`data-bg="home"`): beside the hero text, above it on portrait screens, touring the service shapes. Other pages (`data-bg="page"`): larger, in the bottom-right corner, dimmed to 45% by CSS, neutral or tinted by `bgColour` (service subpages). The clock is kept in sessionStorage so the pose carries over between pages. Reduced motion: one still frame.
- **Redesign in progress (yellow + black, 1-bit):** the palette is two inks (`--color-background` yellow, `--color-foreground` near-black, `--color-muted` dark olive) and the `glass` utility is now a solid plate with a black outline and hard shadow. Home is done; Services, the subpages, Work, About and CV only inherit the palette so far. `SiteBackground.astro` / `site-background.ts` (Three.js) are no longer rendered by `BaseLayout.astro` and are to be deleted with the `three` dependency; the sections above that describe the 3D background, service key colours and `data-svc-*` wiring are historical.
- `src/components/PixelFigure.astro` + `src/lib/pixel-figures.ts` — animated 1-bit pixel figures (`web`, `ai`, `automation`, `dataviz`, `hero`), dependency-free: one hidden WebGL canvas renders each figure at grid resolution (one fragment = one cell, forms filled with dither patterns fixed to the grid), copied into a 2D canvas that CSS upscales by a whole number of device pixels. They run on the clock, independent of the scroll position (a scroll-scrubbed version was tried and dropped); each builds up once, bottom-up through the Bayer matrix, the first time it is on screen. `?t=<seconds>` or reduced motion: one still frame. GLSL pitfall: `half` is a reserved word.
- `PixelFigure.astro` options: `cycle={[...]}` dissolves to further figures in turn through the Bayer matrix (8 s hold, 1.4 s dissolve; not used at the moment), `ripple` sends a ring through the figure from a click or tap (built for the Home hero, switched off there on 2026-11-24 at Giacomo's request; unused now), `replay` rebuilds it each time it comes back on screen (the phone menu's waves, above the links in `Header.astro`). A frozen `?t=` counts the cycle from 8 s, so `?t=16.7` shows a dissolve half-way.
- **Home hero footage**: when `public/video/hero-coding.mp4` exists, the hero dithers that clip live (`video` prop of `PixelFigure.astro`, `figVideo` in pixel-figures.ts: brightness through the Bayer matrix plus inked outlines where brightness changes sharply, frame in the lower right on wide screens and full width along the bottom on tall ones; drawn at `cells={450}`, i.e. 2 CSS px per cell); nothing is drawn while the clip loads; the drawn `figCoder` scene is only the fallback if the clip is missing or fails to load. Make the clip with `scripts/hero-video.sh <recording> [start] [length] [crop] [width] [filters]` (silent, greyscale, 12 fps, about 350 kB for 8 s at 640 px wide, quality crf 24). The current clip is the vertical recording Giacomo preferred, mirrored so he faces the quote: `scripts/hero-video.sh footage/20261124-164735.mp4 4 8 "iw:ih*0.72:0:ih*0.28" 640 "delogo=x=480:y=500:w=100:h=980,delogo=x=490:y=450:w=410:h=140,delogo=x=325:y=1025:w=75:h=85,eq=gamma=1.25,hflip"` (the three delogo boxes smooth the door frame and a light switch out of the wall; the gamma lifts his backlit face). Two landscape recordings were tried and passed over. Raw recordings live in `footage/` (git-ignored); never leave them in `public/`, which is deployed as is. Headless Chrome with `--virtual-time-budget` never loads the video, so check this one in a real browser.
- `src/components/PixelBackground.astro` — page background on every page but Home (rendered by `BaseLayout.astro`, chosen by route): a fixed band along the bottom (`tubes` on Services, `rings` on About, `hero` arches on the CV) or, on a service subpage, that service's figure in the bottom-right corner. Drawn in a darker yellow (16% ink) so text stays readable over it; hidden in print.
- `src/components/HomeHero.astro` — Home: a full-screen hero (quote rising word by word with SplitText, alone on a yellow plate and centred vertically on desktop, over one full-screen animation, the `focus` figure: a flat side view of Giacomo coding (`figCoder`): drawn after his portrait (`src/assets/giacomo-profile-2026.webp`: short dark curly hair, short beard, broad build, dark overshirt with rolled sleeves over a black T-shirt, light trousers), seated on an office chair facing right, arms typing, head nodding and a foot tapping; a desk with keyboard, a monitor turned towards him with code typing itself and a steaming mug; a shelf of books with his camera above it; a ukulele on a stand behind the chair. (First-person versions, flat and ray-marched 3D, were tried and rejected on 2026-11-24, as was a front-facing ukulele player.) on load it gathers out of pixels scattered over the screen; right of centre on wide screens, in the lower part on tall ones), then one full-screen section per service (name, summary, item chips, link to the subpage, beside its figure; text rises in via ScrollTrigger).
- Svelte (`@astrojs/svelte`) is still installed but no component uses it any more; `wrangler.jsonc` sets `nodejs_compat` for its server renderer.

## Astro pitfalls

- `npx astro dev` may report "already running" and keep serving a stale build (old CSS). If styles look missing, `npx astro dev stop`, kill whatever listens on 4321, and start again.

- Don't use a regex containing `<` or `>` in a component's frontmatter: the Astro compiler misparses it and the whole component fails to type-check ("no default export"). Use `replaceAll` with plain strings.

## GSAP notes

- All GSAP plugins are free (gsap ≥ 3.13); SplitText and ScrambleText are used.
- Never put a CSS `transition` on an element GSAP tweens with `autoAlpha`/`from`: the tween settles at opacity 0 and the element stays hidden.
- Kill in-flight tweens (`gsap.killTweensOf`) before staggered enter/leave tweens, otherwise late-starting staggered pieces are left behind.
- Wrap pointer effects in `gsap.matchMedia()` gated on `(prefers-reduced-motion: no-preference) and (hover: hover) and (pointer: fine)` and return a cleanup function.
